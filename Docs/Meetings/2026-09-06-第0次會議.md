## 遊戲機制討論

- [ ] 確認狗仔（DogeEnemy）相關變數意義及修改方式
      對應 `Assets/Script/Enemy/DogeEnemy.cs`、`EnemyBase.cs`（`DifficultyStats`、`phase1CycleInterval`、`phase2CycleInterval`、`jumpDuration` 等）
- [ ] 難易度「變數」由離散值改為連續值，難度暫定 0～5 級
      目前 `EnemyBase.Difficulty` 是 `Easy/Normal/Hard` 三段式 enum，`ApplyDifficulty` 吃三組手調 `DifficultyStats`；改連續值需要重新設計數值插值方式（線性 or 曲線），`LevelManager.difficulty` 欄位也要跟著改型別
- [ ] 預設難易度調降：
  - [ ] 延長敵方出招冷卻（`phase1CycleInterval` / `phase2CycleInterval`）
  - [ ] 降低最大跳躍高度（`jumpDuration` 相關的跳躍參數）
- [ ] 玩家與敵人碰撞關閉
      目前碰撞傷害走 `DogeEnemy.OnCollisionStay2D`；關閉碰撞後攻擊判定要改走別的觸發方式（會影響 contact damage / contact knockback 邏輯）
- [ ] 無敵幀時間綁定於敵人攻擊類型
      現有無敵邏輯只在 `ChargeRamSkill`（玩家大招，`IsActive` 時 `TakeDamage` ×0）；新需求是依「敵人攻擊種類」給玩家不同無敵幀，屬於新機制，需要另外設計掛勾點
- [ ] 大狗叫招式更改：`SonicWave`（旋轉光束）→ 改為扇形彈幕，速度放慢，每隔數顆子彈留大空隙供閃避
- [ ] 技能充能方式架構調整：充能改綁在「技能本身」而非「技能槽」
      現況：`PlayerStats.Charge` 是全角色共用的一份充能資源（`AddCharge`/`SpendCharge`），由 `ChargeRamSkill` 消耗、`Bullet` 命中時 +1；改成每個技能各自持有充能會動到 `PlayerStats` 和 `ISkill` 介面的設計
- [ ] 一技能同步原版（以 teleport 方式完成瞬間移動，無距離限制）
      *（推測對應 `DashSkill`，確切是哪個技能槽建議實作前再跟 Pikapoopowo 對一次）*
- [ ] 二技能撞擊方式改為小範圍追蹤
      *（推測對應 `ChargeRamSkill` 的撞擊判定，從「衝刺撞擊」改成小範圍追蹤鎖定）*
- [ ] 加入自動回血，依角色血量上限和難度調整回血量/速度
